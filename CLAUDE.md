# CLAUDE.md — vexy-mkdocs-tools

Guidance for AI agents (and humans) working in this repository.

## What this is

A small Fire-based CLI that bundles the ProperDocs + MaterialX + `vexy-*` MkDocs
plugin set and wraps the standard site-build pipeline used across all FontLab and
Vexy documentation sites. Consumer repos depend on this tool to build; it is the
shared build surface for the portfolio, so **behavior changes to the build output
ripple to every site**. Be conservative: do not change what `build` produces
without a test proving equivalence.

## The pipeline (`cli.py`)

`CLI` resolves three paths from the site root (defaults, all overridable via
constructor / flags):

- config: `mkdocs/mkdocs.yml`
- source Markdown: `src_docs/md/`
- output: `docs/`

`_find_repo_root` walks up from cwd until it finds a directory holding **both**
`mkdocs/mkdocs.yml` and `src_docs/`. `build` runs: optional Flowmark format →
`_clean_docs` (empties `docs/`, keeps `CNAME`) → `properdocs build` (absolute
paths, so mkdocs resolves the output dir independent of the config location) →
`touch docs/.nojekyll`.

The theme registered by the bundled stack is **`materialx`**, not `material`.

## Conventions

- Python ≥ 3.12, `src/` layout, hatch-vcs dynamic version from `vX.Y.Z` git tags.
- Every source file starts with a `# this_file: <path>` comment.
- Lint/format: `uvx ruff check src tests` and `uvx ruff format`.
- Tests: `uv run python -m pytest -q`. The end-to-end build tests skip when
  `properdocs` is not on PATH.
- Release is tag-driven: pushing a `vX.Y.Z` tag runs `release.yml`, which
  publishes to PyPI via Trusted Publishing (OIDC). `uvx gitnextver@latest .`
  bumps the patch tag and pushes.

## Docs

Two separate doc surfaces, do not confuse them:

- **This repo's own docs**: source in `src_docs/md/`, config in
  `src_docs/mkdocs.yml`, built into `docs/` by `src_docs/build.sh` (ProperDocs +
  MaterialX, strict) and the `Docs` workflow. Served at
  https://vexy.dev/vexy-mkdocs-tools/. Do not edit `docs/` by hand.
- **Consumer sites** use `docs/` as MkDocs *output* with a `.nojekyll` marker.
